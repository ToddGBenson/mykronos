# Retro — 2026-09-05: enabling a control is how you find what was behind it

The brief was one sentence — *oracle should be enabled across all the repos* —
and finishing it took five pull requests on this platform, two on TheHub, and
four new backlog entries. Oracle now has a lane on all five repositories and
portfolio scoring went from **0 scored, 3 failed** to **5 scored, 0 failed**.

The more useful output is the pattern underneath it, which repeated three times
today and which the last two retros also contain: **turning a control on is what
surfaces the defects behind it, and every one of those defects had been sitting
there unreachable rather than absent.** `administration: read` was granted on
2026-09-04 and exposed three. Enabling oracle exposed a fourth that had broken
every risk decision in the estate. Repairing a dead scan lane exposed a fifth.
None was found by a test; 2,587 of those pass.

## What went well

- **Every capability was verified on the live lane, not in the file.** `iac`,
  `qa`, `unit` and `dependencies` were each re-run and watched upload `HTTP 200`
  before being called fixed. The personal-soc oracle gate was applied to
  Concourse and triggered; it failed with a 500, which is how the datetime bug
  turned from a background log warning into something with a cause.

- **The gate that could not run failed instead of passing.** personal-soc's
  oracle job exits 1 with no ingestion token and uses `curl --fail` under
  `set -e`. That is why the 500 was visible at all: a gate that cannot get a
  decision must not report success. The same property made the backend outage
  legible rather than silent.

- **A "no fix available" claim was verified rather than accepted.** The briefing
  said 272 of 275 container findings had no published fix. Before accepting 271
  of them, `apt-cache policy` was run against the `python:3.14-slim` base and
  every installed version *was* Debian's current candidate — checked
  specifically for all 40 HIGH packages. The image had itself been rebuilt from
  that base the same day, so a rebuild closes nothing. Each acceptance carries a
  2026-12-04 review date and re-opens when a vendor ships.

- **Sixteen HIGH findings were read individually rather than batch-closed.**
  Twelve `avoid-sqlalchemy-text` resolved as false positives with the call path
  recorded per site — bound parameters throughout, every interpolation a module
  constant, and one site (`backfill_plaintext`) with no callers at all. Two were
  real and fixed. Two were real and filed. The 12 dispositions each name why,
  which is the difference between clearing noise and hiding it.

- **The regression tests were checked by reverting the fix.** The two new
  capability-audit tests were confirmed to fail without the change and pass with
  it. A test that passes both ways is worth nothing and looks identical to one
  that works.

## What went badly

- **This assessment silently revoked five of TheHub's capability grants, and the
  audit log said it had not.** Enabling `oracle` sent the six capabilities the
  ledger listed; the grant table held eleven. `sync_grants` makes
  `capability_grants` exactly the request and deletes the rest — while the audit
  entry recorded `previous - requested` computed from `row.enabled_capabilities`,
  a different source. It wrote `removed: []`. Twenty-two minutes later TheHub's
  `iac` lane began failing with 403 and four other lanes went green while their
  uploads were refused. B-062; fixed in #216.

- **That same audit field was then believed twice.** Once when the grants were
  deleted, and again an hour later when deletion was ruled out as the cause *on
  the strength of the same `removed: []`*. Two wrong mechanisms were written into
  the backlog entry before the right one — first a token-versus-ledger split,
  then "ingestion enforcement was newly introduced", both stated as fact and both
  corrected. What settled it was reading `sync_grants` against the line that
  writes the audit entry, rather than reading either alone.

- **TheHub's branch decision was reverted by applying a pipeline.** B-045 closed
  on 2026-09-04 by passing `-Branch develop` and leaving
  `set-thehub-pipeline.ps1`'s default at `main`. Applying that script today for
  an unrelated fix printed `Delivering branch 'main'` and moved TheHub back. That
  is the third occurrence of a sentence already written in that script's own
  comment — *"the repository said `develop` while the applied pipeline watched
  `main`, and nothing anywhere reconciled the two"* — this time with the script
  as the thing saying `main`. The default is now `develop`.

- **Four HIGH CVEs were reported as live on the internet-facing application, and
  were not.** osv-scanner runs `--no-resolve`, so it assesses the version a
  requirement *declares*. `cryptography>=42.0.0` was scanned as 42.0.0 against
  containers running 50.0.1, which has none. Stated in a PR description and a
  status report before being checked. Corrected only after running
  `import cryptography; print(cryptography.__version__)` inside the running
  container. B-063.

- **A lesson written down twice in the same file was missed at the third site.**
  `lint-and-types` and `prompt-evals` both carry a comment explaining that
  `bash -ec` plus `pipefail` kills the shell at a pipe before `${PIPESTATUS}` can
  be read — one of them ending *"it is written down here so the next one does
  not"* have to learn it. `dependencies` and `api-inventory` never got it.
  osv-scanner exits 1 **when it finds vulnerabilities**, so TheHub's dependency
  lane worked for exactly as long as there was nothing to find and died silently
  from 2026-09-01 onward, emitting no error at all — not even its own `::error::`
  echo, because the shell was already gone.

- **Governance scores fell and had to be defended as correct.** Every score
  dropped 3–4 points because five more controls now count and three are off
  everywhere. Nothing was turned off; the denominator got honest. This was
  recorded in B-060 explicitly, because a score that only rises as an audit
  widens is measuring the audit rather than the estate — and because the next
  person to see the drop would otherwise read it as a regression.

## Themes

**Recording intent instead of effect is how a system lies without anyone
lying.** `sync_grants` returned exactly what it deleted, and that return value
was spent building a log sentence while the audit recorded a diff computed from
somewhere else. The two agreed for as long as the ledger and the grant table
agreed, which is to say until the first time it mattered. This is the same shape
as the caught-and-logged exception from the 2026-09-03 retro and the same fix:
record the outcome, not the attempt.

**A decision recorded only as an argument reverts on the next routine apply.**
B-045 was closed correctly and did not survive a day, because the decision lived
in an operator's memory of a flag rather than in a default. A default is where a
decision lives if it is to hold. The same is true of `-AllowMissingAzure`, which
had to be passed today and which encodes a real fact — cloud-posture has nothing
to scan — as a command-line argument nobody will remember in a month.

**A finding that names a version is very easy to believe about the thing it is
attached to.** `cryptography@42.0.0` reads as a statement about a running system
and is a statement about a lower bound. The platform presents both identically:
same severity, same ageing, same weight in the Oracle score. Absence and unknown
were separated on 2026-09-03 for the same reason; declared and resolved is the
next pair, and B-063 is the entry.

**Noise does not hide signal politely.** TheHub's backlog was 93% findings that
could not be acted on — 271 OS packages with no vendor fix, 12 false positives
— and the two things underneath were a script injection in the production deploy
workflow and an unauthenticated cipher on the most sensitive table in the
application. Neither was reachable until the noise was cleared with reasons. The
raw score fell 180.9 → 124.9 across that work *without a single vulnerability
being fixed*, which is the measure of how much of it was never risk.

**The controls that fail closed are the ones that told the truth today.** A gate
that exits 1 without a token, a `curl --fail` that turns a 500 into a red lane,
a schema guard that fails a build. Against them: a coverage check that reports
`event_driven` without asking whether a job exists (B-061), an upload step ending
in `|| echo "the scan verdict above still stands"` that let four lanes go green
while being refused, and an audit that recorded a field it did not write. Failing
closed is expensive on the day and cheap on every other day.
