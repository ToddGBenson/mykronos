# Retro — 2026-09-13: merged is not shipped, and I proved it on my own workstation

Fifty-nine pull requests merged across five repositories in two days. None of
the mykronos ones were running. The backend serving this platform was an
image built eight days earlier, and I did not discover that by scanning for
it — I discovered it because the operator said *"everything should be merged
and all committed code should be in production"* and I went to check.

That is the retro. Everything else is detail.

The last three retros were about *turning a control on is what surfaces the
defects behind it*, and then about *the code that tells you whether something
worked is the code nothing tells you about when it stops working*. This one is
the same failure with the subject changed to me: **I spent two days writing up
other people's gaps between the artifact that was measured and the artifact
that was running, while sitting on exactly that gap.** I confirmed the class
twice independently — a `perl-base` finding against a package that was not in
the running image, and a `next 16.3.0` advisory against a version nobody
deployed — wrote both up, and did not once run `docker inspect` against my own
backend.

## What went well

- **The nginx header chain was predicted and it held.** Issue #265 claimed one
  config change would close 41 of TheHub's 70 open DAST findings. It was not an
  estimate dressed as a number; it came from grouping the findings by rule and
  counting. Six PRs later TheHub's DAST count is 3. The prediction is the part
  worth keeping — a remediation whose effect you can state in advance is one
  you understand.

- **The highest-severity thing found this run was found by reading, not
  scanning.** keel and binnacle both interpolated `workflow_dispatch` inputs
  into shell, in a job holding `id-token: write`, **before** the human approval
  gate. No scanner flagged it. It surfaced from asking what the approval gate
  was actually protecting, and noticing that the answer was "a step that had
  already run." Fixed in both repos the same hour (keel #84, binnacle #9).

- **One claim was measured instead of asserted.** The previous retro described
  findings closing on the silence of a tool that could not see them. Rather
  than repeat the story, I audited every closure in the window: **23 of 25 were
  correct, 1 was wrong, 1 ambiguous.** That is a far less dramatic number than
  the narrative implied, and it is the number. This is the shape every other
  claim in these retros should have and mostly does not.

- **Four more controls that exist but do not run.** A backup codec that never
  ran (#347), two alert evaluators wired to nothing (#353), a dead IPS (#354),
  and a `tests/security/` directory no lane gates (#357). The previous retro
  named this class; finding four more in two days says it is a standing
  property of this estate, not an anecdote.

## What went badly

- **I took TheHub's `unit` lane red with two of my own merged PRs.** One
  disabled foreign keys in a way that only worked on SQLite, so PostgreSQL CI
  raised `ForeignKeyViolation` on all four cases; the other put a test in
  `tests/security/`, which no lane runs. Seven scan lanes sit behind `unit`
  (#331). I broke the gate I exist to keep green, and it stayed broken until
  TheHub #333. The SQLite-vs-PostgreSQL split is a real fixture problem, but
  the reason it reached `main` is that I ran the suite where it was convenient
  rather than where CI runs it.

- **My own fix turned a checker on, and the checker flagged itself.** #308 made
  `check_ai` scan from the right root; it then flagged its own test corpus,
  took `oracle-gate` red and blocked `promote` for a day (#356). Worse, the
  first explanatory comment I wrote in the fix quoted the offending pattern
  verbatim, and the checker flagged the comment. Two iterations to write a
  sentence that describes a string without containing it.

- **Three failed attempts before mykronos actually deployed.** Built from the
  wrong branch. Then `--build` did nothing, because the compose file has
  `image:` and no `build:` — images come from the pipeline, and the eight-day-old
  `:latest` was silently reused. Then nearly mounted `/dev/null` as the GitHub
  App private key, because `MYKRONOS_GITHUB_APP_KEY_HOST_PATH` is set by
  `deploy.ps1` and is absent from `backend/.env`. Each attempt *reported
  success*. Each is the same defect I wrote up in other people's pipelines four
  times this run.

- **Fifty-nine stories created, four closed.** The backlog grew by 55 net in
  two days. Creating a story is cheap, produces a visible artifact, and feels
  like progress; it defers all of the cost and none of the credit. A run that
  opens fifteen times more work than it closes should say so in its first
  paragraph, not its fifth.

- **Eight public corrections, and some of the corrections were wrong.** #291's
  correction was itself incorrect — the Cloudflare tunnel bypasses the Windows
  firewall entirely, so the rule I "corrected" to was irrelevant. #360 proposed
  making `escapeHtml` quote-safe, which would have been a regression, because
  `escapeAttr` already exists with 388 call sites; #360's scope also moved
  48 → 100 → 63 across three attempts before a number survived. #338 asked for
  something `sweep_acceptances` already does. #276 was over-broad. #336
  generalised from a 3-of-3 sample against a measured 0-of-59. #339's
  `setuptools` note applied to neither application. #357 called a gated test
  ungated. The pattern is consistent: **the first pass is confident and the
  measurement arrives later**, and the measurement keeps disagreeing.

## Themes

**1. Merged is not shipped, and neither is scanned.** Three independent
confirmations this run that the artifact a finding describes is not the
artifact serving traffic — and then a two-day demonstration of it on this
workstation. mykronos has no check that compares the running image digest to
`main`. It should; that is the single most valuable story in the 59, and it did
not exist until the operator asked the question that produced it (#361).

**2. Controls that exist but do not run is a standing property, not a phase.**
Three retros have now named it. Four more instances in two days. The estate has
more dormant controls than live findings, and nothing measures the ratio.

**3. The correction rate is the metric.** Eight corrections across roughly
thirty write-ups is a ~27% first-pass error rate on published claims. Diagnosis
is fast, confident and cheap; verification is slow, quiet and the only part
that was ever load-bearing. The closure audit — 23 of 25, stated as a count —
is the one piece of this run's output I would defend without re-checking, and
it is the one piece that cost the most to produce.

**4. The operator asked the question the platform should have asked.**
"Is everything in production?" is a query, not a conversation. That it had to be
typed is the finding.
