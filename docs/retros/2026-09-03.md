# Retro — 2026-09-03: a DevSecOps brief delivered, and what shipping against live data kept catching

The day started with a UX review and a DevSecOps assessment, and ended with a
twenty-two item brief delivered in full. Thirty pull requests (#177–#206), eight
decisions (D-100 through D-107), five new backlog entries, and one estate that
went from 431 blocked findings to 32.

The more useful output is a pattern that repeated four times and is worth naming
before it happens a fifth: **every defect found today was found by rendering a
shipped feature against production data, and not one was found by a test.**

## What went well

- **Every refusal was written down as a refusal, not omitted.** SSDF omits PO.1
  and PO.2 and says why. The test estate names seven kinds of testing nothing
  here does. Consult names six questions it cannot answer. In each case the
  absent half is the half that makes the present half trustworthy, and in each
  case it would have been easier to ship only the green rows.

- **No single number, three times running.** SSDF has no percentage, the test
  estate has no maturity score, and the CVSS work deliberately did not become a
  second in-house risk figure. D-103 records the reasoning once so it does not
  have to be re-argued: the items are not equally weighted or equally
  applicable, so a denominator that includes things a repository is correct not
  to do produces a score that punishes being right.

- **The brief's hardest ask turned out to be the standard's own default.** "Base
  scores on what is known about the system, otherwise assume the worst" is
  exactly what CVSS environmental scoring does — every undefined modifier takes
  the base value. That meant implementing a published formula rather than
  inventing one, and it means a repository that has told the platform nothing
  can never be quietly discounted.

- **The schema drift guard earned its keep.** `ControlDrift`'s columns had no
  defaults, and the guard failed the build rather than letting a column ship
  that could not later be added to a populated table. It was right and the test
  said exactly why.

- **Operator-blocked work was named rather than half-built.** Five entries
  (B-018, B-035, B-042, B-043, B-044) each record the input they need and the
  concrete payoff. B-044 is the standout: one permission grant lights four
  features, and the fact that all four report honestly that they cannot see is
  the proof they were built correctly.

## What went badly

- **The SSDF module understated adherence on its first production render.**
  PO.4, RV.2 and RV.3 reported `not_evidenced` against 1,382 risk decisions, 110
  remediation events and 43 dismissals. The mapping listed `oracle`, `patchwork`
  and `aegis` as *capabilities*, and a capability resolves through scan health —
  but they produce records, not scan runs. They would have read "enabled but has
  never reported" forever. Fixed in #199. A module whose entire claim is that it
  does not overstate adherence understated it, which is the same failure pointed
  the other way.

- **Consult shipped with a divergence from the tab it cites.** It computed its
  SSDF answer with empty control sets while the Adherence tab read governance
  live. They agreed only because the App lacks `administration: read` on every
  repository in this estate — the day that is granted, the tab would say a
  practice is met and the sentence linking to it would still say unevidenced.
  Consolidated to one code path in #202.

- **`fixable: true` on an empty `fixed_version`.** `is not None` where `bool(…)`
  was meant. Found by rendering the finding record against live data.

- **A published artifact was corrected in place after claiming the component
  inventory was empty.** The query used `/data/lake`; the real path is
  `/data/datalake`. The claim was wrong, said so in the commit and the PR, and
  the artifact was rewritten rather than quietly patched.

- **`git add -A` swept two untracked marketing drafts into a feature commit.**
  Caught before merge, removed in a follow-up commit rather than a force-push.

- **Two test expectations were wrong before the implementation was.** A CVSS
  base score hand-calculated as 1.8 was asserted as 2.0, and a test assumed
  raising every security requirement would raise the score when `MISS` is capped
  at 0.915. Both were fixed as *test* bugs, and the second became a pinned test
  explaining why the cap binds — so nobody later "fixes" the mapping that is
  working correctly.

## Themes

**A caught failure is the silent kind, and it repeats at every layer.** The job
runner catches every exception, logs it, and retries — correct behaviour that
makes a job which has thrown for a fortnight indistinguishable from one that has
never had a problem. `last_run_at` stays fresh the whole time. That is the same
shape as a scan lane that fails and freezes findings open, and the same shape as
`weights()` returning an empty dict from the 2026-08-29 retro. The fix each time
is to record the *outcome*, not the attempt.

**Detection that waits for a person is not monitoring.** Governance was read
live on every panel render, so the console always showed the truth — and a
repository nobody opened was a repository nobody was watching. `self_check` was
worse: it ran only when somebody typed a command. Both are now on timers. The
distinction between a dashboard and a control is who has to be looking.

**Absence and unknown are different, and conflating them costs the alert.** A
control that becomes `unknown` is a read that failed, not a control that was
removed. A CVE with no NVD record is not a CVE with a zero score. A lane with
runs and no coverage document is not a lane at 0% coverage. Every one of those
pairs got a separate state today, and the reason is always the same: they send
somebody to different places.

**Rendering against live data caught four defects that tests did not.** Not
because the tests were bad — 2,558 of them pass — but because each defect was a
wrong *assumption about the shape of production data*, which a fixture cannot
contradict. `fixable` on an empty string, a capability that produces no scan
runs, an estate where governance is unreadable everywhere, a lake path with a
different name. The habit worth keeping: deploy, then read the surface back
before calling it done.

**The platform's capabilities are ahead of its wiring.** Coverage is plumbed end
to end and no pipeline writes it. The oracle writes 1,382 decisions nothing read
for SSDF. The notifier is configured and addressed to nobody. Four features wait
on one permission grant. This was already noted on 2026-09-03's earlier
assessment and it held for the whole day — which is a better problem than the
reverse, and a different one from the backlog this project usually collects.

## Open work, noted

All five are in [OPERATOR-TASKS.md](../OPERATOR-TASKS.md) with step-by-step
procedures. Summarised here because the retro is where somebody looks first:

- **B-044 — grant `administration: read`.** Five minutes, unblocks four
  features. `repo_governance` holds zero rows, ever. Do this one first. Note
  that GitHub *requests* a permission change rather than applying it — the
  installation owner must accept it separately, which is the step that gets
  missed.
- **B-035 — the Slack webhook URL.** One environment variable; converts the
  whole platform from pull to push.
- **B-042 — coverage.** Two lines and a CI-budget decision: roughly 3–4 minutes
  added to every pull request. The Harness tab correctly says "never measured"
  until then.
- **B-018 — the Azure principal.** A decision, not a defect. Restore it or
  disable `cloud` on TheHub and record why.
- **B-043 — a model credential for free-text Consult.** Optional; the grounded
  answers work without it, and the six refusals stay when it arrives.

Two things carried forward that are not operator-blocked:

- **The first job row on the platform-health page lands 30 minutes after a
  deploy** (`fix-verification` has the shortest interval). Verified as designed
  in unit tests; confirm on the live page next session.
- **`environment_for`'s two judgement calls** — `public` data mapping to `CR:M`
  rather than `CR:L`, and `internet_facing=True` setting no modifier — are
  stated in one place precisely so they can be disagreed with. Worth a second
  opinion once real risk profiles exist to score against.
